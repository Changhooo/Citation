# CitationClaw Progress

更新日期：2026-05-07

## 当前阶段

项目已经进入可运行 MVP 调试阶段：本地 FastAPI/Jinja Web app 可以通过 Scholar 镜像搜索论文 A、采集引用论文群 B、按高引用规则生成候选论文群 C、下载镜像右侧可见 PDF、支持人工批量上传 PDF，并导出结果。

## 已完成

- 支持以 Scholar 镜像作为论文搜索和 cited-by 采集入口。
- 支持用户切换镜像，例如 `https://sc.panda985.com/`。
- 支持识别动态 cited-by ID，而不是写死某个镜像的 ID。
- 支持采集 B 论文列表，并在每页采集后保存，便于断点续跑。
- 支持在采集 B 时自动尝试下载右侧直接可见的 PDF。
- 支持 PDF 本地查看入口。
- 支持用户批量上传 PDF，系统按论文标题进行模糊匹配。
- 支持按 B 中引用量 Top 10% 生成 C。
- 支持导出 JSON、CSV、ZIP。
- 已将项目推送到 GitHub：`https://github.com/Changhooo/Citation`。

## 当前重要问题

### 1. C 目前只能代表高引用论文

当前 C 的生成逻辑是：从 B 中按引用量筛选高引用论文，例如 Top 10%。这只能说明论文影响力较高，不能说明这些论文的作者一定是大佬，也不能说明作者具有 Fellow/院士头衔。

后续必须继续做：

- 对 C 中高引用论文的作者进行联网搜索。
- 判断作者是否具有 Fellow/院士等头衔。
- 每个判断必须保留 URL 证据，优先官方网页。
- 给出作者消歧置信度。
- 低置信度不能自动确认，必须进入人工审核。
- UI 中要明确区分：
  - C 入选原因：高引用。
  - 作者身份判断：Fellow/院士证据。

### 2. 引用上下文抽取存在失败样例

当前发现一个失败样例：

任务中显示：

```text
引用上下文抽取完成：C 共 8 篇，本地 PDF 4 篇，抽到上下文 0 条，缺 PDF 4 篇。
```

这说明系统已经找到部分本地 PDF，但没有成功抽取出引用论文 A 的上下文，因此正/负/中立判断没有正确执行。

后续必须继续做：

- 检查目标论文 A 标题和参考文献条目的匹配规则。
- 检查 PDF 文本抽取质量。
- 支持更多引用格式：
  - 数字型 `[12]`
  - 作者年份型 `(Smith et al., 2020)`
  - 上标引用
  - 脚注引用
  - 多引用 `[12, 15, 18]`
  - 范围引用 `[12-15]`
- 默认抽取前一句、命中句、后一句，并标出命中句。
- 抽到上下文后再执行正/负/中立判断。
